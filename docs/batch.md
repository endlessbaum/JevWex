# 一括判定

左メニューの「一括判定」から、同じ判定基準で複数のデータを順番に判定できます。モデル・ハードウェア・起動時のモデル復元は既存の仕組みを共用します。画像も文章も端末内で処理します。

## データの取り込み

- **文章一覧**：1行を1件として貼り付けます。空行を除き、最大10,000件、UTF-8換算20 MiBまで。
- **CSV・表の貼り付け**：CSV/TSVファイル、Excelなどからコピーした表を取り込めます。ファイルはUTF-8またはShift_JISを選択。カンマ・改行・引用符を含むCSVセルに対応しています。XLSXファイルそのものの読み込みには対応していません。
- **画像一覧**：PNG・JPEGを最大10枚選択します。1枚を独立した1件として扱います。1枚10 MiB・2,000万画素まで。すべての画像に添える補足文章は任意です。画像対応モデルと画像用ファイルが必要です。

表の場合は「取り込み内容を確認」を押し、見出し行の有無、判定する内容の列、データ名の列を選びます。「行全体を使う」も選べます。名前が重複していても番号で区別します。先頭10件をプレビューできます。選んだ内容列が空の場合は、その行を消さず、実行時に失敗として記録します。表の列数不一致や閉じていない引用符は、取り込み時に案内します。

「CSVの入力例を使う」で、問い合わせ3件のサンプルを入力できます。改行を含む1件の文章は、文章一覧ではなくCSVの引用符で囲んだセルを使用してください。

## 共通の判定基準と実行

一括判定ページを初めて開いた時点の「判定」ページの基準をコピーします。その後は一括判定用として編集できます。「判定ページの基準をコピー」で取り直せます。選択式・段階評価・当てはまりと、基準名・ラベル・説明の編集方法は通常の判定と同じです。

「新しく一括判定」で、開始時のデータ・基準・表示名を固定して順次処理します。既存の公開wllama APIを使い、モデルをデータごとに読み直しません。履歴は共有しません。実行中は一括入力と基準を固定し、モデル切替・単独判定・ハードウェア再適用を禁止します。モデルが返した生の応答は、通常の判定と同じく解析前にConsoleへ出します。

「中止」は現在の推論へ中止を伝え、次のデータへ進みません。完了済みの結果は残ります。「未完了・失敗分を再開」は開始時のデータ・基準を使い、完了済みを再実行せずに続けます。再開には同じモデルを読み込んだままにする必要があります。終了後に入力を編集しても、その変更は新しい一括判定にのみ適用されます。

行単位の入力エラー・不正なモデル出力・長さ制限は、その行を失敗として次へ進みます。ランタイム障害など継続できないエラーでは停止します。全基準が成功した行を完了と扱い、一部の基準が失敗した行を集計に混ぜません。タブを閉じると入力・結果は失われるため、必要な結果はダウンロードしてください。

## 個別結果と集計

個別結果は50件ずつ表示し、データ名・内容での検索、状態での絞り込みができます。「内容と判定の内訳」を開くと、元の文章・画像、各基準の結果、候補ごとの重み、重みの集中度を確認できます。理由文をモデルから生成する機能は追加していません。

集計対象は、全基準の判定が完了した行だけです。失敗・中止・未処理件数は別に表示します。

| 判定方法 | 集計内容 |
| --- | --- |
| 選択式 | 選ばれたラベル別の件数・割合 |
| 段階評価 | scoreの平均・最小・最大、各段階の平均の重み |
| 当てはまり | 平均・最小・最大、50%以上／未満の件数 |

割合・当てはまり・重みの集中度は正答率ではありません。段階評価の平均は各行の連続値scoreを平均し、ラベルへ丸めません。

- **個別結果をダウンロード**：UTF-8 BOM付きCSV。番号、名前、入力文章、画像ファイル名、状態、エラー、各基準の値を含みます。
- **集計をダウンロード**：CSV。基準別の件数・割合・平均などと、対象件数を含みます。百分率の項目名には単位を付けています。
- **詳細データを保存**：JSON。実行時の基準・表示名・各行の入力と状態・結果・生成文字・候補logprobs・計算値・実行情報・集計を含みます。画像バイナリや未加工応答の全体は含みません。

実行途中でも、その時点までの結果を保存できます。CSVでは数式として認識される接頭辞にアポストロフィを付ける対策をしています。すべての表計算ソフトや再保存後の挙動を検証したものではありません。

## 一括判定追加時の検証記録

以下は旧方式（数値JSON生成）での記録です。現在は数値JSONを生成させないため、「範囲外の数値出力」の失敗例も旧方式の観察です。候補トークン方式への変更後の一括テストは [token-readout-test-results.json](token-readout-test-results.json) の `batch` と [verification.md](verification.md) を参照してください。

### 実行済み

- `npm run typecheck`、単体テスト100件、`npm run build`。
- CSVの引用符・改行・BOM・TSV、10,000件の入力受付と上限超過、行エラーの分離、直列実行、中止・再開、入力の固定、全3種の集計の分母と値、CSV数式対策を単体テスト。
- 既存UIの実Chrome拡張テスト7項目。
- `JEV_BATCH_VISION=1 npm run test:extension:batch`：Chrome for Testing 145.0.7632.6のビルド済み拡張で7項目成功。Qwen2.5-0.5B-InstructとLFM2.5-VL-3BをWebGPUで使用。
- CSVファイルと貼り付け、複数行セル、同じ名前の行、通常の判定との基準の分離、3種混在の実判定、空行内容の失敗分離、平均値の再計算照合、個別内訳・検索・絞り込み・CSV/JSON保存。
- 実推論を中止して完了分を保持し、表示上の基準を編集した後も開始時の基準で再開できること。完了分の結果が変わらないこと。
- 55件の文章を実際に連続判定し、50件＋5件のページ表示を確認。
- 10件の画像バッチ：正常なPNG9枚はそれぞれの画像を1枚ずつ渡して3種判定、壊れた画像1枚は失敗として分離。11枚の選択は拒否。
- 390pxの画面幅、実行中の入力ロック、外部HTTP通信・ページ例外がないこと。

機械可読記録：[batch-test-results.json](batch-test-results.json)。テスト画像は生成した単色PNGです。分類の正答率を評価するテストではありません。検証中には、段階評価でモデルが範囲外の値を生成して行が失敗する例も確認しました。通常の単独判定と同じ形式検証で扱い、集計へ混ぜません。また、以前の画像テストと同様、青い画像でも最高scoreになる誤判定は残っています。
