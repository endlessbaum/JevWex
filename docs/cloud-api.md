# JEV互換API接続

確認日：2026-09-30。TypeSafe公式の[API reference](https://docs.typesafe.ai/api)と[Models](https://docs.typesafe.ai/models)を参照しています。OpenAIのDecisions APIは、利用者の指定により公開仕様を確認できるまで保留です。Responses API等による代替実装は含めていません。

## 設定と選択

1. モデル管理でローカルGGUFを読み込みます。これがフォールバック先です。
2. 「使用するモデル」内の「JEV互換APIの設定」に設定名、送信先URL、モデルID、APIキーを入力します。フォーム最後の「設定を保存して使用する」を押すと、一覧に登録されて使用中になります。API設定は複数保存できます。初期値は `https://api.typesafe.ai/v1/systemone` と `jev-latest`。URLはベースURLではなく、リクエストを送る完全なURLです。
3. 保存したAPIはローカルGGUFと同じ一覧に表示されます。各行の「使用する」で切り替え、「設定を変更」で設定名・URL・モデルID・待ち時間・フォールバック・キーを変更できます。保存すると編集したAPIが使用中になります。保存後のフォームは新規登録用に戻るため、そのまま次のAPIを追加できます。拡張版ではその送信先のアクセス許可を求めます。保存・選択操作だけでは判定用データを送信しません。
4. 単体・一括・Webページ判定が選択した接続先を使います。一覧のローカルモデルを読み込むか、待機中のローカルモデルの「使用する」でローカルに戻せます。

フォールバックを無効にすればローカルモデル未読込でもAPIだけで利用できます。オンの場合、未読込でのAPI選択を拒否します。既存の起動時モデル復元・サイズ制限は維持し、新たなモデルの自動ダウンロードは行いません。

拡張版ではAPIキーと設定をAPIごとのIDで `chrome.storage.local` に保存し、Chrome再起動後も再入力不要です。以前の1件保存形式もキーを維持して一覧へ引き継ぎます。同じモデルID・送信先でも複数の設定とキーを区別します。保存後は入力欄を空にし、「APIキー設定済み」と送信先のホストだけを表示します。キーの変更は新しいキーを入力して上書きし、旧キーを履歴として残しません。各行の「削除」または「このAPI設定を削除」で、その設定とキーだけを削除します。選択中のAPIを削除した場合はローカルに戻り、他のAPI設定は引き続き利用できます。キーは設定IDと送信先URLに結び付け、別のURLへの設定変更ではキーの再入力が必要です。新しいAPI設定には別途キーを入力します。

「設定を保存して使用する」は常に保存と選択をまとめて行い、次の判定から変更を反映します。フォールバックが有効でローカルが未読込の場合、保存・選択の前にローカルモデルの準備を求めます。判定中の編集・切り替えはできません。「保存済み設定で接続テスト」はフォームで編集中の保存済みAPI（新規登録フォームでは現在使用中のAPI）に短い判定を1回送り、フォールバックを行わず接続を確認します。

APIキーの読み出しと通信はService Workerで行います。Content Scriptにはキーを返さず、保存情報の状態とAPI処理結果だけをモデル管理画面へ返します。APIキー未設定時は通信せず、認証失敗・利用制限・通信失敗を区別します。[BYOKの構成・検証](byok.md)

Web版はAPI設定一覧のみlocalStorageへ保存し、APIキーは設定ごとに管理タブのメモリ内に保持します。両版とも接続先の選択状態は保存せず、再読込・次回起動はローカルです。HTTP APIサーバーの専用推論モデルにはこの画面設定を適用しません。

## 通信と互換範囲

`POST` のJSON本体は `{state, questions, model}`、認証はキー指定時のみ `Authorization: Bearer …` です。本文にはクラウド用モデルIDを渡し、ローカルIDやUI内部の `cloud:…` IDは送りません。レスポンスは `{model, answers}` を要求し、追加のusage等は結果に取り込みません。

JevWex自身のHTTP APIの `{response: {model, answers}, diagnostics}` 形式も受け付けます。この場合は送信先を `/api/v1/evaluate` の完全なURLにし、モデルIDに接続先の状態APIが示す `loaded.model` を指定します。接続先のdiagnosticsは取り込まず、ブラウザで通信・検証した診断を作成します。

choice・score・noulの型、質問IDの完全一致、候補キー、有限な0〜1の確率を検証します。choiceは最大確率の候補、scoreは確率加重値との整合とlegendを確認します。確率和には小数丸めの許容誤差 `0.0001`、scoreの整合には `0.01` を設けます。値の補完や均等分布への置換はしません。API側の確率・confidence・scoreと実際のモデルIDを保持します。内部の入力上限（質問16件、choice32候補、score2〜10段階等）は引き続き適用します。

単体・一括・Webページ判定の文章と基準が送信対象です。画像を含む入力はAPIへ送らず、フォールバックが有効なら入力全体をローカルへ渡します。フォールバック無効時やローカルが画像非対応の場合は明示的に失敗します。

HTTPSまたはループバックHTTPに対応し、URL内のユーザー情報・クエリ・フラグメントは受け付けません。Cookieを送らず、リダイレクトは拒否します。APIキー・任意のエラー本文をログや結果ファイルに含めません。拡張版の通信先はService Workerが保存済み設定から選び、Content ScriptからのAPI操作・任意URLやヘッダーによる通信を受け付けません。Web版では送信先のCORS対応が必要です。

## フォールバックと中止

クラウドの応答待ちは初期値60秒（1〜600秒）。ネットワーク・HTTPエラー・タイムアウト・不正回答時は、読み込み済みローカルモデルで同じ要求全体を一度だけ実行します。ユーザーの中止、入力不正、モデルID不一致では再実行しません。クラウドの部分結果とローカル結果を混ぜません。ローカル側も失敗した場合はそのエラーを返します。

ローカル実行にはハードウェア設定の既存の待ち時間を適用します。Webページ判定の通信待ちはクラウド待ち時間も含めます。クラウド失敗後も接続先の選択は維持するため、次の要求では再度APIを試します。

単体結果には実際のモデルと切替理由を表示します。各結果JSONの `diagnostics.provider` は `jev` またはフォールバック時の `local`。`diagnostics.fallback` に元接続種別と理由を保存します。クラウドの `readout_method` は `jev_api`、`confidence_method` は `provider` です。一括結果は行ごとの実際のモデルと診断を保持します。
