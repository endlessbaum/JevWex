# 拡張内モデルダウンロード

## 操作

画像対応モデルの新規リポジトリ取得では、公開APIで本体とmmprojを選び一組で保存します。直接URLや既存の本体キャッシュへの追加には、画面で対応する画像用ファイルのURLを指定できます。[画像モデルの操作と検証](vision.md)

1. 拡張を再読み込みし、JevWexの判定タブを開き直します。
2. 左メニューの「モデル管理」を開きます。「モデルをダウンロード」欄を使います。
3. `unsloth/Qwen3-0.6B-GGUF` のようにHugging Faceの `所有者/モデル` を入力します。公開ファイル一覧から `Q4_K_M` を選び、取得するファイル名とURLを表示します。末尾の空白やコピー時に混入した `&#x20;` も除去します。別の量子化を使う場合はHTTPS直接URL `https://huggingface.co/所有者/モデル/resolve/リビジョン/ファイル.gguf` を指定できます。Webの閲覧用 `/blob/` URLではありません。
4. 「ダウンロード」を押します。取得量／全体サイズを表示します。不明な場合はサイズ不明と表示します。「ダウンロード中止」で中止できます。
5. 保存完了後にモデル一覧から選択し、「読み込む」を押します。「判定へ進む」で判定画面へ移動します。画面移動ではモデルを解放しません。

「入力例を使う」は検証用Qwen 0.5BのURLを入力欄へ入れるだけです。自動でダウンロード・モデル切替・推論は行いません。任意の対応GGUFを利用でき、判定アダプタに特定モデルを固定していません。

リポジトリ名の指定では `main` の `Q4_K_M` を使用します。見つからない場合はエラーを表示し、別の量子化へ自動で切り替えません。その場合は取得したいGGUFの直接URLを入力してください。

## 保存・通信

- `@wllama/wllama@3.6.1` の公開 `getHFModelSource`、`ModelManager.downloadModel`、`getModels`、`CacheManager.delete` と既存OPFSを使用します。独自ストレージ、パッチ、binding、WASMビルドは追加していません。
- ダウンロード済みモデルはページ再読込後も選択できます。ロード時・判定時はキャッシュを使います。同じURLの完了済みモデルはネットワークへ接続せず再利用します。リポジトリ名入力でも、そのリポジトリの `main` に対応する `Q4_K_M` のキャッシュが1つならオフラインで再利用します。
- ブラウザによるストレージ削除・拡張アンインストールでキャッシュを失う場合があります。永続保存権限を要求していません。ローカルファイル入力とは別経路です。
- 中止／失敗時には公開APIの処理終了を待ち、今回の未完了ファイルをキャッシュから削除します。未完了ファイルをモデル一覧に登録しません。公開APIのリポジトリ一覧取得と配布版内部のメタデータHEAD/小さなraw-file要求はAbortSignalに対応していないため、中止完了までその応答待ちになる場合があります。一覧取得中に中止した場合はモデル本体のダウンロードへ進みません。モデル本体GETにはsignalを伝播します。
- host_permissionsとconnect-srcは `https://huggingface.co`、実測したリダイレクト先 `https://us.aws.cdn.hf.co` のみに限定しています。ほかのホストへリダイレクトされた場合は失敗表示し、無制限に権限を広げません。
- 取得するのはモデルデータとそのサイズ等のメタデータだけです。実行JS/WASM/Workerは引き続き拡張に同梱します。stateや判定結果をダウンロード要求へ含めません。

## 対応範囲

公開された単一GGUFのみ。認証付き・gatedモデル、別配信元、分割モデルのURLダウンロードは未対応です。分割モデルは既存のローカルファイル選択を使用してください。URLのユーザー情報、fragment、認証queryは拒否します。`?download=true` は取り除いて同じキャッシュIDとして扱います。
