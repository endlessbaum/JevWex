# 画像を使う判定

Webページのimg・サムネイルも、URL別条件の対象に含めて判定できます。対象の選択、項目ごとの画像分離、配信元の許可については [Webページ画像の操作](web-pages.md#画像サムネイルを判定する) を参照してください。以下は管理画面で手動添付する場合の操作です。

## 操作

1. 「モデル管理」で `LiquidAI/LFM2.5-VL-3B-GGUF` など、対応する公開GGUFリポジトリ名を入力してダウンロードします。「画像モデルの入力例」でも入力できます。
2. 新規リポジトリでは本体Q4_K_Mと、同じリポジトリにある画像用ファイル（mmproj）を公開wllamaの選択規則で取得します。取得ファイル名を画面に表示します。直接URL指定や本体のみの既存キャッシュに画像用ファイルを追加する場合は、「画像用ファイルを指定する」に対応するmmprojの直接URLを指定します。
3. 「読み込む」を押します。「判定」で画像対応と表示されたら、画像を追加します。端末のモデルファイルを使う場合は、本体と対応するmmprojを一緒に選択します。
4. 文章は任意です。判定基準を設定して判定します。添付したすべての画像が、それぞれの判定基準へ渡されます。サムネイルの「削除」で取り除けます。

PNG・JPEGに対応し、最大4枚、1枚10 MiB・2,000万画素まで。モデルの処理容量により、これより少なくても上限に達する場合があります。画像を減らすか、ハードウェア設定で扱える量を増やしてください。

モデル本体と画像用ファイルは同梱しません。LFM2.5-VLのライセンスは売上規模に関する商用利用条件を含む独自ライセンスです。取得・利用前に [検証モデルのライセンスと配布元](../README.md#動作検証に使用したモデル同梱なし) を確認してください。

文章専用モデルで画像を付けたまま判定すると、対応モデルの準備を案内して停止します。画像を黙って無視しません。画像の内容や結果は外部へ送信せず、自動保存もしません。結果ダウンロードには画像名・形式・容量・寸法を含め、画像本体は含めません。画像だけで実行した際のstateには「添付画像を判定してください。」を入れます。

## 実装と互換性

モデル本体をGPU、画像用mmprojをCPUで処理したい場合は、ハードウェア設定の「画像処理（mmproj）」で「CPUを使う」を選んで再読み込みしてください。[mmprojの配置設定](hardware.md#画像用ファイルmmprojをcpuで処理する)

`@wllama/wllama@3.6.1` の通常依存を維持しています。`ModelSource.mmprojUrl`、`loadModel`、`getLoadedContextInfo().has_image_input`、`createChatCompletion` のユーザーメッセージ内 `{type: "image", data: ArrayBuffer}` を使用します。画像用ファイルは既定では本体のCPU/GPU設定に従い、「画像処理（mmproj）」でCPUに固定することもできます。判定対象のモデル名は固定していません。

JEV入力のstate/questions構造は維持し、画像バイナリはローカル判定処理の別引数です。開始時に画像と入力を複製し、各質問には個別のバッファを渡します。画像編集も既存の結果世代管理へ反映し、実行中に添付を変更した結果は採用しません。入力はブラウザでデコード確認し、プレビューURLは削除・ページ終了時に解放します。

公開ライブラリ本体、binding、WASM、manifest権限には変更を加えていません。すべてのvisionアーキテクチャでの互換性を保証するものではありません。

参考：公開版同梱の `src/types/oai-compat.ts`、`src/huggingface.ts`、`src/model-manager.ts`、`src/wllama.ts` と [LiquidAIの公式モデルカード](https://huggingface.co/LiquidAI/LFM2.5-VL-3B-GGUF)。

## 画像入力追加時の検証記録

以下は旧方式（数値JSON生成）での記録であり、現在の出力形式ではありません。候補トークン方式への変更後も画像テストを実行しています。その結果は [token-readout-test-results.json](token-readout-test-results.json) の `vision` / `vision_results` と [verification.md](verification.md) を参照してください。

### 実行済み

- 型チェック、単体テスト91件、ビルド。
- ビルド済み拡張で既存UIの7項目（ページ切替、基準編集、モバイル幅等）。
- `node tests/extension/vision.mjs`：Chrome for Testing 145.0.7632.6、8項目成功。初回は公式配布先から実際に約2,153 MiBを取得。再実行では保存済みファイルを使用。
- LFM2.5-VL-3B-Q4_K_M + mmproj-LFM2.5-VL-3B-Q8_0、CPU8スレッド、WebGPU31層、context4096で画像対応ロード。再読込後の本体・画像用ファイルの組合せ保持とオフライン再利用。
- 赤と青の256×256 PNGそれぞれで、文章入力なしのchoice/noul/scoreを実行し結果JSONを取得。3基準で約3.0〜3.2秒。choiceは赤→red、青→blue、赤へのnoulは1→0。2枚同時の全3基準も実推論成功。
- 画像のプレビュー・削除・壊れた画像の拒否、390px幅、文章専用SmolLM2に切り替えた際の画像拒否。推論中にHTTP通信なし。

**精度上の観察：** 青=0、紫=1、赤=2という段階評価では、青の画像でもモデルが `{"p0":0,"p1":0,"p2":1}` を生成し、score2になりました。実行と形式検証は成功していますが、この基準の意味的な判定には失敗しています。画面の重みや点数はこの生出力の計算結果であり、正答率ではありません。詳細は [vision-test-results.json](vision-test-results.json) の生出力と入力を参照してください。
