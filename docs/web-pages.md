# Webページ判定とURL別の条件管理

## 使い方

1. `npm run build` のあと、Chromeの拡張管理画面で `dist` を読み込み直します。既存のJevWexタブ・パネルも開き直してください。
2. 管理用タブの「モデル管理」でモデルを読み込みます。従来の画面は管理画面として残り、モデル・ハードウェア・URL別条件の設定を行えます。キャッシュ済みの最終モデルは従来どおり自動復元します。
3. Webページで拡張アイコンを押すと閲覧用パネルが開きます。「＋ 判定条件を作成」から名前・対象URL・適用範囲・判定基準を入力し、作成画面内の「対象を調整する」で範囲を指定します。「対象と基準を保存」でセットとして保存し、保存直後はオンになります。
4. URLに合う条件を一覧のスイッチでオン／オフにします。オフの条件も一覧に残り、切替状態を保存します。スイッチは保存条件全体の有効状態であり、その適用範囲に含まれる他のURLにも反映します。
5. 「オンの条件で判定」を押すと、各条件に保存した対象の最新の文章を取得し、その条件の基準で順に判定します。同じURLでも「商品リストを1件ずつ」「レビュー欄をまとめて」など別々に保存できます。進捗・結果は**Webページ右上のオーバーレイ**に表示します。

保存済みの条件は一覧の「対象・基準を編集」から開きます。範囲編集画面の「この対象を使う」は編集中の対象を変更し、条件画面の「対象と基準を保存」で両方をまとめて確定します。保存せず閉じた場合は以前の対象・基準を維持します。他の条件の対象は変更しません。管理画面でも各条件の対象を表示し、対象URLのページを開いていれば「対象を調整する」から同じ範囲編集画面を使えます。

管理用タブの読み込み済みモデルを共有するため、判定中は管理用タブを開いたままにします。パネルを閉じても実行は続きます。モデル管理・一括判定は管理用タブに残しています。「管理画面 ↗」「管理画面で編集 ↗」は既存の管理用タブを再利用します。

パネルを開いた時、タブ切替時、ページの読み込み完了時、SPAのURL変更時は現在のページを取得し直します。管理用タブでモデルを準備したら、判定したいWebページのタブに戻ってください。同じURLのまま本文が追加された場合は「現在のページを再取得」を押します。権限不足・タブ終了時は以前の本文と条件一覧を消します。新しい条件用の範囲が見つからない場合も、保存済みの条件はそれぞれの対象で実行できます。

### ページを取得できない場合

パネルを開いたまま「現在のページを再取得」を押すと、その時点の本文を取得し直します。別タブ・別サイトへの移動などで読み取り権限がない場合は、ボタンが**「このサイトを許可して再取得」**に変わります。押してChromeの確認画面で許可すると、そのまま本文を取得します。パネルを開き直す必要はありません。許可を断った場合は取得せず、再度操作できます。確認中に別のページへ移動した場合は、その古い操作で移動先の表示を上書きしません。

許可は現在のプロトコル・ホストのみに要求し、次回もそのサイトで再取得できます。Chromeのホスト権限は同じホストの全パス・全ポートを含み、サブドメインは含めません。拡張機能のサイトアクセス設定で取り消せます。サイトへの許可を保存したくない場合は、対象ページのツールバーでJevWexアイコンを押して一時的な読み取り許可を与える方法も使えます。[Chromeの任意の権限](https://developer.chrome.com/docs/extensions/reference/api/permissions)、[activeTabの許可範囲](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab)

取得失敗時には、権限不足・対象外のページ・タブ終了・その他の読み込みエラーを案内します。本文が空の場合も表示します。新規作成用の文章は「新しい条件の対象を確認」、保存済みの各条件の文章は対象の調整画面で確認できます。サイト固有の問題を調べる際は、対象URLとここに表示される文章・エラーを確認してください。

### 入力欄を監視して自動判定する

1. 判定条件の「対象を調整する」で、HTML構造またはページ上から入力欄を選びます。input（text・search・url・email・tel）、textarea、contenteditableの編集欄に対応しています。パスワード・非表示のinputは対象外です。
2. 入力欄を選ぶと、その現在の値がプレビューされます。空欄のままでも「この対象を使う」で確定できます。フォーム全体を選んだ通常の本文取得ではinput・textareaの値を取り込みません。
3. 条件画面の「入力監視をオンにする」をチェックし、判定基準と一緒に保存します。監視は初期状態ではオフです。保存済みの入力欄の条件には、パネルの一覧にも独立した入力監視スイッチが表示されます。

監視中は、対象の入力イベントが止まって約50ms後に、変更された欄の条件だけで判定を開始します。50msは判定開始までの待機であり、結果が出るまでの時間はモデルと入力に依存します。日本語の変換中は実行せず、変換確定後から待機します。オンにした瞬間の既存の値は自動判定せず、次の入力を待ちます。

判定中に再入力すると、古い自動判定を中止して最新の値で実行し直します。空欄・空白だけの値は判定せず、前の自動判定結果を消して次の入力を待ちます。監視オフ・条件の無効化・削除・ページ移動は待機中や実行中の自動判定を止めます。手動判定中の入力は、手動判定が終わってから最新の変更を実行します。

監視スイッチ・対象・判定基準は保存されます。パネルを閉じても監視は続き、ページ読み取り権限がある場合は再読み込み後にも復元します。権限がないページでは、対象ページで拡張アイコンを押すか「このサイトを許可して再取得」で許可してください。管理画面のモデルは準備したままにします。指定した欄がDOMの更新で置き換わっても同じ一意のセレクターで追跡します。ページ側のプログラムがinputイベントを発火せずに値だけを変更した場合は自動判定しません。

`npm run test:extension:input-monitor` は、入力値の取得、監視ON/OFF、連続入力の50ms待機、IMEの変換待機、対象外の欄の無視、古い結果の破棄、空欄、許可済みページの再読み込み、textarea・contenteditableを検証します。判定器にはテスト用応答を使い、モデル精度や推論時間は評価しません。

## 本文の範囲を選ぶ・子要素を除外する

既定では表示中の `main`・`[role=main]`・`article` のうち文字数が多い要素を本文候補として選びます。候補がなければ `body` を使います。パネルには選ばれた要素と、対象／ページ全体の文字数を表示します。

判定条件の作成・編集画面内の「対象を調整する」を押すと、ページ上に範囲編集画面が開きます。

1. 上側の「対象と除外」に本文候補、親への移動、ページ上での対象選択、HTML構造ツリーをまとめています。「この要素以下に絞る」は、その要素と子孫だけを本文範囲にします。ツリーのすぐ上の「親要素へ」で一段広げられます。詳しい説明は「操作と判定の説明」で開けます。
2. HTML構造の「含む」のチェックを外すと、その要素と全子要素を除外します。「除外中」のチェックを戻すと解除します。ページ上では対象範囲内を Alt＋クリックして除外・解除できます。除外された要素の子孫を Alt＋クリックすると、その親の除外を解除します。Alt＋クリックではリンクを開きません。
3. 対象を緑枠、除外を赤枠・斜線で表示します。対象の文字数と実際に渡す文章のプレビューを見て調整します。設定・プレビュー部分は画面サイズに合わせてスクロールでき、下部の確定・閉じるボタンは常に表示します。リンク先プレビューの取得中・成功件数・失敗は下部に表示し、失敗の詳細はプレビュー内でも確認できます。ツリーは先頭250要素までで、必要なら対象を狭めるかページ上で選びます。除外設定は共通・個別の合計64件までです。共通除外で対応する要素はまとめて1設定と数えます。
4. 「この対象を使う」で条件の作成・編集に戻り、「対象と基準を保存」で確定します。ほかの保存済み条件には影響しません。

「判定する内容」の下にプレビューをまとめています。リンク先を判定する場合はリンク先本文の先頭3行（各行100文字まで）と取得結果を表示し、元ページの0文字のプレビューは表示しません。表示を省略しても判定用の本文は短縮しません。

対象のCSSセレクター・除外・1件ずつの指定は、各条件の `contentScope` に基準と一緒に保存します。本文そのものは保存しません。「配下のページ」「サイト全体」の条件では、同じ範囲指定を適用先の各ページに使います。従来の対象なしの保存条件は、登録URLに保存されていた範囲を一度取り込んで移行します。登録URLの範囲がなければ本文の自動選択です。

`jev-content-scope:<URL>` は新しい条件を作るための初期対象として残ります。クエリを区別し、`#`以降は無視します。後からこの初期対象を変えても、保存済みの対象と基準のセットは変わりません。

保存した対象・除外の要素が存在しない、または一意に決まらない場合は、その条件をエラーとして表示し、ほかの条件は続行します。範囲をページ全体へ広げて判定しません。該当条件の「対象・基準を編集」で対象を選び直すか、調整画面の「自動選択に戻す」を押して保存します。IDがない要素にはHTML内の位置を使うため、サイトの構造変更後はプレビューを確認してください。編集はページ移動で終了します。

パネル・ショートカットとも、各条件に保存した対象を使い、ページ上の文章の選択では切り替わりません。各条件の文章は対象の調整画面で確認できます。パネル上部の「新しい条件の対象を確認」は新規作成用の範囲です。文字数はモデルのトークン数ではありません。本文は1件につき最大48,000文字まで取得し、モデルのコンテキスト上限の検査は引き続き行います。

## リスト・カードを1件ずつ判定する

HTMLの構造で `ul` などの親要素を展開し、その下の「判定方法」を選びます。

- **子要素を1件ずつ判定**：その親要素を対象範囲にし、繰り返される子要素をそれぞれ別の入力にします。
- **まとめて判定**：選んだ親要素の本文を1つの入力にします。子要素の除外設定は維持します。

同じ親の下にある同じタグ・共通クラスの子要素を検出します。`ul`・`ol` のリストだけでなく、カードが並ぶ `div` や表の行を含む `tbody` にも使えます。1件分の候補が複数ある場合は「1件分の子要素」で選べます。共通クラスを持つ候補を初期選択し、リスト見出しなどを一緒に含めないかプレビューで確認できます。ツリーに表示しきれない場合は「ページ上で対象を選ぶ」で親要素を選び、その判定方法を指定します。

青い点線と項目番号で1件分の境界を示します。プレビューも「1件目」「2件目」…に分かれるので、リストの見出しや別の領域が混ざっていないか確認して対象と基準を保存します。まとめて判定する設定に戻す場合は、同じ親要素の「判定方法」を「まとめて判定」に切り替えて保存します。以前保存した1件ずつの設定も、この選択欄に反映します。

実行時は**項目ごと・オンの条件ごとに別の入力**を送り、ほかの項目の文章を混ぜません。オーバーレイには項目番号・本文冒頭・条件名・結果を表示します。1項目の入力・出力エラーはその項目に表示して次へ進みます。中止時は完了した結果を残します。管理画面との切断・応答タイムアウト・判定条件の変更・ページ移動では実行全体を止めます。

空欄・非表示の項目と、除外した要素の内側は読み取りません。同じ文章の項目も別件として扱います。対象の項目が見つからない場合や、同じ要素が入れ子で重複して指定された場合は、その条件の判定を止め、ほかの条件は続行します。

リスト内の子要素のチェックを外すと、**同じリストの全項目で対応する子要素を除外**します。チェック表示・赤枠・プレビューも全件に反映し、どれか1件でチェックを戻すと全件の同じ除外を解除します。ページ上での除外操作も共通です。項目そのもののチェックを外した場合は、その1件だけを除外します。

共通除外は、リストの場所・項目のパターン・各項目から見た子要素の位置を保存します。項目固有のIDを使わないため、再取得時に増えた項目にも適用します。対応する子要素がない項目はそのまま読み取ります。`li` のリストや共通クラスのカードなど、繰り返しを認識できる場合は「1件ずつ」の指定前でも共通除外になります。以前保存した個別の子要素の除外も、読み込み時に同じ扱いにします。対応関係はタグの階層と同種タグ内の順序によるため、構造の異なる項目やサイト改修後はプレビューを確認してください。

項目数と全項目の合計文字数に固定上限は設けません。実行開始時点でページに読み込まれている要素を1件ずつ順番に処理し、途中で中止できます。1件あたりの取得上限48,000文字とモデルのコンテキスト上限は引き続き適用します。無限スクロール・ページ送り先は自動で読み込まず、後から読み込まれた項目は再取得で反映します。繰り返し設定も各条件の対象に保存されます。

## リンク先の本文を判定する

条件の「対象を調整する」で `a` タグに対象を絞ると、**リンク先の本文を取得して判定する** が自動でオンになります。カードやリストの親を対象にして、この設定を手動でオンにすることもできます。調整画面には取得したリンク先のURL・タイトル・本文のプレビューを表示します。

未許可のリンク先は取得しません。「この対象を使う」で条件画面へ戻り、「リンク先の取得を許可」で表示されたホストを許可すると、本文を確認できます。「リンク先を取得して確認」で再取得し、対象と基準を保存してください。許可済みのサイトは調整中にもプレビューを取得します。プレビューは対象内の先頭4リンクの本文各3行だけです。実行時は各項目のリンク先を改めて取得し、モデルの入力上限の80%以内に収まる本文全体を判定します。プレビューに出していない続きも判定に使います。

一覧で「子要素を1件ずつ判定」を選ぶと、その項目内のリンク先だけを入力にします。広告などのリンクは構造のチェックを外して除外でき、共通除外も反映します。結果は元のリンク・カードに対応して表示します。リンク先の取得に失敗した項目はエラーにし、ほかの項目は続行します。元のページの文章に置き換えて判定することはありません。

1件の入力につきリンクは4件までです。判定に渡す本文の合計文字数（区切り・省略表示を含む）は、読み込み済みモデルのコンテキスト上限 × 0.8 の小数点以下を切り捨てた値以下にします。例えば上限4,096なら最大3,276文字です。複数リンクをまとめる場合も、合計でこの上限を守るよう本文の先頭を分配します。トークン数と文字数の違いに備えた余裕であり、実際のプロンプトのトークン数検査は従来どおり行います。モデル未準備のプレビューは暫定819文字で表示し、実行時に準備済みモデルの上限で取得し直します。クラウド選択中はフォールバック用のローカルモデルの上限を使い、ローカル未準備ならハードウェア設定の文章量を使います。

HTTP(S)の公開HTMLをCookie・Refererなしで取得し、`body` 内の `#contents`、`.contents`、`contents` タグの順で対象を選びます。どれもなければ `body` 配下だけを使います。スクリプト・ナビゲーション・フォーム・非表示要素などは除外し、判定には本文だけを渡します。ページタイトル・リンク名・URLはプレビューに表示しますが、判定本文には含めません。HTMLは1 MiBまで、取得は各15秒までです。リンク先を別タブで開かず、スクリプト・画像・iframeを実行・読み込みません。そこから先のリンクも取得しません。JavaScriptで本文が生成されるページ、ログインが必要なページ、PDF・ダウンロード、ページ内だけのリンクは対象外です。リダイレクトには追従しないため、その場合は最終URLのリンクを対象にしてください。`contents` がないサイトでは、body内の周辺の文章を含む場合があります。

保存条件には対象とリンク先判定の設定だけを保存し、取得した本文は永続保存しません。リンク先取得には外部通信が発生します。モデル管理の初期設定ではローカルモデルで判定し、JEV互換APIを選んだ場合は取得した文章と基準をそのAPIへ送ります。[クラウドAPIの設定](cloud-api.md)。画像を含む判定とリンク先判定は切り替えて使います。

## 画像・サムネイルを判定する

管理画面で画像対応モデルと対応する画像用ファイル（mmproj）を読み込みます。条件の「対象を調整する」で **対象内の画像も判定する（画像対応モデル）** をオンにしてください。`img` 自体を対象に絞ると自動でオンになり、文章がない画像だけの対象も保存できます。この設定は対象・判定基準とセットで保存します。既存の文章だけの条件には画像を追加しません。

YouTubeなどの一覧では、カードの親で「子要素を1件ずつ判定」を選び、画像を含めます。各項目の画像だけをその項目の文章・基準と一緒に渡します。アバターや広告は構造のチェックを外して除外でき、共通除外も画像に適用します。`picture` / `srcset` は `img.currentSrc` の表示中の画像を使います。遅延読み込み前の画像や、まだDOMに追加されていない項目は自動でスクロールして読み込みません。

条件の作成・編集画面に画像枚数と未許可の配信元を表示します。「画像の取得元を許可」で表示したホストだけの読み取り許可を付けます。画像配信元は本文のサイトと異なる場合があります。取得時にも許可を確認し、未許可ならその項目をエラーにします。許可済みならショートカットでも画像を判定できます。CSPのconnect-srcはHTTP/HTTPSへの接続を許可し、ホスト権限は画像の配信元ごとに要求します。全サイトへの読み取り権限を一括付与しません。[Chrome拡張のクロスオリジン通信](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests)

PNG・JPEG・WebP・AVIF・GIFをブラウザでデコードし、PNGとしてVLMへ渡します。アニメーションは最初のフレームのみです。1項目4枚、各画像10 MiB・2,000万画素までで、全リストの項目数には制限を追加していません。モデルのコンテキスト上限は別に適用します。SVG、blob URL、CSS背景画像、動画本体、iframe・Shadow DOM内部は対象外です。画像取得にはCookieやRefererを送りません。認証が必要な画像や取得に失敗した画像はエラーになり、ほかの項目は続行します。

画像は実行時に管理用タブから配信元へ取得し、ローカルモデルへ渡します。画像取得には外部通信が発生しますが、外部の推論APIには送りません。JEV互換APIの選択中も、画像付きの入力はフォールバックが有効なら全体をローカルで処理し、無効ならエラーにします。条件にはセレクターと画像の有効設定を保存し、画像本体は永続保存しません。画像対応でないモデルを使うと案内を表示し、画像を無視して文章だけで判定することはありません。

## パネルなしで判定する

既定ショートカットは **Alt+Shift+J** です。URLに合うオンの条件ごとに、保存された対象と基準のセットで実行します。1件ずつ／まとめての指定や除外も条件ごとの設定を使います。ページ上の選択文章で保存対象を上書きせず、パネルも開きません。

Chromeの拡張機能 → キーボードショートカット（`chrome://extensions/shortcuts`）で変更できます。競合などで未割当の場合はそこで登録してください。パネルには実際に割り当てられたキーを表示します。

オーバーレイの「中止」で実行を止めます。×またはEscで閉じると、まだ実行中なら中止します。URLの変更・再読み込み・タブ終了でも対象の実行を中止し、移動先に古い結果を表示しません。同じタブの二重実行は開始せず、モデルが他の判定で使用中の場合は案内を表示します。管理画面のモデルが未準備、オンの条件がない場合もオーバーレイに理由を表示します。Chrome内部画面など注入できないページでは拡張アイコンに「!」を表示し、アイコンのタイトルに理由を示します。

### 結果から対象を確認する

結果オーバーレイの見出し「⠿ JevWex · ページ判定」をドラッグすると移動できます。見出しにフォーカスして矢印キーでも移動でき、Shiftを押すと移動幅が大きくなります。結果の追加・判定完了・同じページでの次の判定でも位置を保ちます。画面サイズが変わったときは画面内に収め、長い結果をスクロールしても見出しは上部に残します。

結果パネルは対象に重なっても自動で透過せず、表示を安定させます。背後のコンテンツを読むときは見出しの「たたむ」で結果部分を隠し、「結果を表示」で戻せます。判定中の更新でも折りたたみ状態を保ち、戻したときは結果内のスクロール位置を復元します。折りたたみ中も見出しのドラッグや矢印キーで移動でき、新しい判定を開始すると結果を表示します。

展開中のパネルの端・四隅をドラッグすると、幅と高さを変更できます。右下のつまみは Tab で選び、矢印キーで20px、Shift＋矢印キーで60pxずつ調整できます。ダブルクリックまたは Home キーで標準の幅・自動の高さに戻ります。判定中の更新、折りたたみからの復帰、同じページの次の判定でも変更したサイズを保ちます。画面が狭くなると収まるサイズに調整し、画面を広げると指定したサイズに戻します。収まらない結果はパネル内でスクロールできます。

オーバーレイの結果にカーソルを合わせると、対応する要素までページをスクロールし、青枠と背景色でハイライトします。項目別判定はその1件、まとめて判定は取得した対象範囲、画像だけの判定はその画像を示します。カーソルを外すと解除します。Tabキーで結果にフォーカスした場合やクリックでも対象を表示できます。

判定時の要素自体を参照するため、リストの順序が変わっても同じ要素を示します。対象が削除・置換された場合は再判定を案内し、同じ位置に追加された別要素へ結果を付け替えません。結果追加時は結果欄のスクロール位置・フォーカスを保持し、ページのスクロールやレイアウト変更にはハイライトを追従させます。閉じる・Esc・ページ移動・次の判定開始でハイライトを片付け、元の要素のスタイルは変更しません。

## URLの適用範囲

| 範囲         | 例                              | 対象                                                       |
| ------------ | ------------------------------- | ---------------------------------------------------------- |
| このURLのみ  | `https://example.com/news?id=1` | 同じURL。クエリは区別し、`#`以降は無視                     |
| 配下のページ | `https://example.com/news/`     | `/news` と `/news/…`。`/newsletter` は含まず、クエリは無視 |
| サイト全体   | `https://example.com`           | 同一プロトコル・ホスト・ポートの全パス                     |

サブドメインやhttp/httpsの違いは別サイトとして扱います。認証情報を含むURLとhttp/https以外は保存できません。実行順は完全一致、長いパスの配下、サイト全体。同じ優先度では条件名・ID順です。条件は選択式・段階評価・当てはまりを設定でき、1条件につき1〜16基準です。保存時に基準名・ラベル・説明・段階順などを検証します。

一度の実行では開始時にオンだった条件を使います。個々の条件は推論の前後に保存内容を確認します。実行中に対象の条件を変更・無効化・削除した場合は、その条件の結果を表示せず再実行を案内します。途中まで完了した条件の結果は残ります。

## 取得・保存・構成

- 選んだ本文要素をHTMLの構造に沿って読み取り、除外した子要素・非表示要素・スクリプト・フォームの入力値を省きます。img画像は画像設定で含められます。iframe内部、Shadow DOM内部、PDF、Canvas内の文字、Chrome内部ページ・ストア等は対象外です。input/textareaを選択中の場合は選択文章として読み取りません。オーバーレイや範囲編集画面の内容は本文取得に含めません。
- 本文・選択文章はそれぞれ先頭48,000文字までで、切り詰めを表示します。判定時は文章・基準の合計65,536文字とモデルのコンテキスト上限も検証します。
- 条件は `chrome.storage.local` の `jev-site-rule:<ID>` に保存し、`contentScope` に対象、`criteria` に基準を保持します。本文・結果を含まず、クラウド同期もしません。オン／オフは最新の保存条件を読み直して変更し、別画面で編集された基準を古い内容で上書きしないようにします。
- アイコンで取得したURL・タイトル・本文・選択文章は `chrome.storage.session` の `jev-page-capture:<windowId>` に一時保持します。ブラウザ終了・拡張再読込・ウィンドウ終了で削除します。パネルを閉じるだけではsessionデータは残ります。
- タブごとの実行状態（ID・状態・進捗メッセージ）は `jev-page-job:<tabId>` に一時保存します。本文・判定結果は保存しません。ショートカットで取得した本文は実行中のメモリ内だけに保持します。
- `panel.html` は推論ランタイムを持ちません。実行ボタンとCommands APIは共通のService Worker処理を呼び、拡張オリジンのBroadcastChannelで管理用タブのModelSessionに依頼します。Service Worker自身ではモデルを動かしません。ユーザーが実行した判定の処理中だけ、Chrome APIの呼出しでWorkerのアイドル終了を防ぎます。個々の推論には4分の待機上限があり、タイムアウト時は中止します。
- オーバーレイは実行ごとに注入し、closed Shadow DOMでWebページのCSSから分離します。本文をHTMLとして挿入せず、ラベル・結果はテキスト表示します。document IDとURLを確認して表示対象を固定します。常駐content scriptは使いません。
- パネルから現在のタブのURLを特定するため `tabs` 権限を使用します。HTTP(S)のホストは `optional_host_permissions` に宣言し、再取得時に必要なホストだけを `permissions.request` で要求します。全サイトへの本文アクセスを一括で要求・付与するものではありません。

API設計の参照: [Chrome activeTab](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab)、[Service Workerのライフサイクル](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)、[Chrome Storage API](https://developer.chrome.com/docs/extensions/reference/api/storage)。
